GoAuto: predicting monthly service revenue for dealerships

Group project for CMPT 2500 (ModelOps team): taking a machine learning model from a notebook to a tested, containerised API.

The problem

A partner business records every service visit at its dealerships. Managers need to know how much service revenue each dealership will bring in next month, so they can plan staffing and parts. We built a model that predicts revenue for each dealership by month.

My role

I took the Docker, logging and Docker Hub work in Lab 4, and rebuilt the earlier labs on the GoAuto project, and other labs

What we did

  • Turned individual service visits into one row per dealership per month.
  • Built features from past revenue (lag and rolling averages), service count, average revenue per service, month, year and dealer.
  • Trained a Gradient Boosting regressor and tracked experiments with MLflow.
  • Served predictions through a Flask REST API with input validation, batch requests and a versioned endpoint.
  • Packaged the API and MLflow in Docker, ran them together with Docker Compose, and automated common commands in a Makefile.
  • Used DVC to track data and models, and Git branches and pull requests for team review.

What we found

Seasons and paid services features mattered most.

Responsible AI and limits

  • Privacy: the real data comes from a partner and includes vehicle identifiers, so it is not published. The repository uses a small made-up sample for tests.
  • Limits: the model predicts revenue from past patterns, so it can miss one-off events such as a dealership closing or a price change.
  • Validation: the API rejects missing or out-of-range inputs instead of guessing.
  • Traceability: MLflow records each training run, so we can show which settings produced which result.

What I would improve

Monitoring the model after release, testing on a later time period, and adding more automated tests.
